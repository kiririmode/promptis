# Python差分レビュー

以下の観点でPythonの差分をレビューしてください:

## レビュー観点

### 1. 型ヒントと型安全性
- 型ヒント（Type Hints）が適切に使用されているか
- 関数シグネチャが明確か（引数・戻り値の型）
- mypy等の型チェッカーで検出可能なエラーがないか

### 2. 例外処理
- 適切な例外の捕捉と処理が行われているか
- 過度に広範な`except:`の使用がないか
- カスタム例外クラスの設計が適切か
- リソース解放（ファイル、DB接続等）が保証されているか（`with`文の使用）

### 3. 並行性・非同期処理
- スレッドセーフな実装になっているか
- 非同期処理（async/await）の適切な使用
- デッドロックやレースコンディションのリスクがないか
- Global Interpreter Lock (GIL) の影響を考慮しているか

### 4. パフォーマンス
- リスト内包表記やジェネレータの適切な使用
- 不要なループやO(n²)のアルゴリズムがないか
- メモリ効率的な実装（大量データの処理）
- データベースクエリのN+1問題がないか

### 5. セキュリティ
- 入力値の検証とサニタイゼーションが適切か
- SQLインジェクション、XSS等の脆弱性がないか
- 機密情報（パスワード、APIキー等）のハードコードがないか
- 安全でない関数（`eval()`, `exec()`, `pickle.loads()`等）の使用がないか

### 6. コード品質
- Pythonic な書き方になっているか（PEP 8準拠）
- 複雑度が高すぎる関数がないか（単一責任の原則）
- マジックナンバーやハードコードされた値がないか
- ドキュメント文字列（docstring）が適切に記載されているか

### 7. 依存関係
- 標準ライブラリで代替可能な外部ライブラリの使用がないか
- 非推奨（deprecated）のAPIやライブラリの使用がないか
- バージョン互換性の問題がないか

## 出力形式

指摘事項がある場合は、以下の形式で記載してください：

**[カテゴリ] 指摘内容**
- 問題点の詳細（該当行番号も記載）
- 影響範囲とリスクレベル（高/中/低）
- 推奨される対応策（修正コード例も含める）

問題がない場合は「問題なし」と記載してください。

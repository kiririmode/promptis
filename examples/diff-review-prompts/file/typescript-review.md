# TypeScript/React差分レビュー

以下の観点でTypeScript/Reactの差分をレビューしてください:

## レビュー観点

### 1. 型安全性
- `any`型の使用が最小限に抑えられているか
- 型アサーション（`as`）の使用が適切か
- ジェネリクスが効果的に使用されているか
- Union型、Intersection型が適切に定義されているか
- 型ガード（Type Guard）による安全な型の絞り込み

### 2. 非同期処理
- Promise、async/awaitの適切な使用
- エラーハンドリングが適切に実装されているか
- 並列実行可能な処理が順次実行されていないか（Promise.all活用）
- メモリリークの可能性（イベントリスナー、タイマー等の解放）

### 3. React特有の観点（.tsx）
- コンポーネントの責務が適切に分割されているか
- Hooksの使用ルールに従っているか（依存配列、条件分岐内での使用禁止等）
- 不要な再レンダリングが発生しないか（useMemo、useCallback、React.memo）
- useEffectの依存配列が適切か
- キーの使用が適切か（リスト表示時）

### 4. パフォーマンス
- 重い計算処理が適切にメモ化されているか
- バンドルサイズへの影響（不要な依存の追加）
- 遅延ロード（lazy loading）の検討
- 大量データのレンダリング最適化（仮想化等）

### 5. セキュリティ
- XSS脆弱性がないか（dangerouslySetInnerHTMLの使用）
- CSRFトークンの適切な処理
- 機密情報のフロントエンドへの露出
- APIキーやシークレットのハードコードがないか

### 6. コード品質
- ESLint/Prettierルールに準拠しているか
- 適切な命名規則が使用されているか
- マジックナンバーや重複コードがないか
- エラーメッセージが分かりやすいか
- コメントが適切に記載されているか（複雑なロジックの説明）

### 7. アクセシビリティ（UI関連）
- ARIA属性が適切に設定されているか
- キーボード操作に対応しているか
- セマンティックHTMLが使用されているか
- 色のコントラスト、フォントサイズが適切か

### 8. テスタビリティ
- ユニットテストが書きやすい構造か
- 外部依存の注入（DI）が適切に行われているか
- モック化しやすい設計か

## 出力形式

指摘事項がある場合は、以下の形式で記載してください：

**[カテゴリ] 指摘内容**
- 問題点の詳細（該当行番号も記載）
- 影響範囲とリスクレベル（高/中/低）
- 推奨される対応策（修正コード例も含める）

問題がない場合は「問題なし」と記載してください。

# SQL差分レビュー

以下の観点でSQLの差分をレビューしてください:

## レビュー観点

### 1. 後方互換性
- スキーマ変更が既存のアプリケーションコードと互換性があるか
- カラム削除やデータ型変更による破壊的影響がないか
- 段階的なマイグレーション戦略が必要か

### 2. ロック影響
- ALTER TABLE による長時間のテーブルロックが発生しないか
- オンライン変更可能な手法（pt-online-schema-change等）の検討
- 本番環境でのダウンタイムリスク

### 3. インデックス設計
- 新規カラムに対する適切なインデックスが設定されているか
- 不要なインデックスが削除されているか
- 複合インデックスのカラム順序が適切か
- クエリパフォーマンスへの影響

### 4. データ整合性
- NOT NULL制約、UNIQUE制約、外部キー制約が適切か
- DEFAULT値の設定が妥当か
- CHECK制約によるビジネスルールの強制

### 5. マイグレーションの可逆性
- ロールバック手順が明確か
- DOWN migrationが適切に実装されているか
- データ損失のリスクがないか

### 6. パフォーマンス
- 大量データに対するUPDATE/DELETEの影響
- N+1クエリの可能性
- クエリの最適化（JOINの効率化、サブクエリの見直し等）

### 7. セキュリティ
- SQLインジェクションの脆弱性がないか（動的SQL使用時）
- 機密データの暗号化やマスキング
- 権限管理（GRANT/REVOKE）の適切性

## 出力形式

指摘事項がある場合は、以下の形式で記載してください：

**[カテゴリ] 指摘内容**
- 問題点の詳細
- 影響範囲とリスクレベル（高/中/低）
- 推奨される対応策（代替実装やマイグレーション戦略）

問題がない場合は「問題なし」と記載してください。

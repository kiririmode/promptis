# スキーマ変更の整合性チェック

データベーススキーマやデータモデルの変更における整合性を確認してください。

## チェック観点

### 1. スキーマ変更の完全性
- データベーススキーマの変更に対応するマイグレーションファイルが含まれているか
- ORM（TypeORM、Sequelize、SQLAlchemy等）のモデル定義が更新されているか
- スキーマ定義ファイル（schema.prisma、Protobuf、GraphQL schema等）の更新

### 2. マイグレーション戦略
- マイグレーション手順が明確に定義されているか
- 段階的な適用計画（Blue-Green Deployment、カナリアリリース等）
- ロールバック手順の準備
  - DOWN migrationの実装
  - データ損失のリスク評価
  - バックアップ戦略

### 3. データ整合性
- 既存データに対する影響分析
  - NOT NULL制約の追加時のデフォルト値処理
  - 外部キー制約の追加時の既存データ検証
  - データ型変更時の互換性確認
- データ移行スクリプトが必要な場合の実装
- 整合性制約（UNIQUE、CHECK等）の妥当性

### 4. アプリケーションコードとの同期
- スキーマ変更に対応するアプリケーションコードの更新
  - モデルクラス、エンティティクラスの更新
  - クエリやビジネスロジックの修正
  - データアクセス層（DAO/Repository）の変更
- 新規カラム/テーブルへのアクセスロジックの追加

### 5. パフォーマンス影響
- インデックスの追加・削除による影響
  - クエリパフォーマンスの改善/劣化予測
  - ディスク容量への影響
  - 書き込みパフォーマンスへの影響
- 大量データに対する変更のダウンタイム予測
- オンライン変更手法（pt-online-schema-change等）の検討

### 6. 環境間の同期
- 開発、ステージング、本番環境でのスキーマバージョン管理
- マイグレーション適用順序の明確化
- 環境変数や設定値の更新

### 7. ドキュメントとテスト
- ER図やスキーマドキュメントの更新
- マイグレーションテストの実施計画
- データベース単体テストの更新
- データ移行の検証方法

## 出力形式

以下の形式でスキーマ変更の整合性チェック結果を報告してください：

### スキーマ変更サマリー
- 変更されたテーブル/カラム一覧
- 変更タイプ（追加/更新/削除）

### 整合性チェック結果
**[OK/NG] チェック項目**
- 詳細説明
- 問題がある場合は具体的な指摘と推奨対応

### リスク評価
- データ損失リスク: [高/中/低]
- ダウンタイムリスク: [高/中/低]
- ロールバック可能性: [可/条件付き/不可]

### 推奨デプロイ手順
1. 事前準備（バックアップ等）
2. マイグレーション適用順序
3. 検証方法
4. ロールバック手順

問題がない場合は「スキーマ変更の整合性に問題なし」と記載してください。
